# 推し旅 LIVE LIFE — 推し活人生ゲーム Web試作版

ファンが主人公の、完全ソロ＋CPU・12週間の縦断プロトタイプです。探索→カード獲得→20枚編成→4曲のライブ→報酬→次の週→最終リザルトを実際に操作できます。アイドル育成・企業経営ゲームではありません。

## 起動と検証

Node.js 22以降を推奨（検証環境：Windows / Node 24.14.1 / npm 11.11.0）。

```powershell
npm install
npm run dev
```

ブラウザで **http://127.0.0.1:5173/** を開きます。開発サーバーはローカルホストにのみバインドします。

```powershell
npm run build
npm test
```

`dist/` が静的配布物です。`base: './'`、クライアント側URLルーターなしのため、GitHub Pagesのサブディレクトリでも動作する構成です。HTTPサーバーで配信してください。公開・Git初期化・GitHub作成・push・デプロイは行っていません。

ブラウザスモークは別ターミナルで開発サーバーを起動した状態で実行します。

```powershell
npm run dev -- --port 5173
# 別ターミナル
npm run test:smoke
```

`scripts/smoke.mjs` はインストール済みMicrosoft Edgeをヘッドレスで使います。Edge以外の環境では `channel: 'msedge'` を利用可能なブラウザに変更してください。証跡は `test-results/` に保存されます（Git対象外）。このテストは独立したブラウザプロファイルを使い、通常のブラウザのセーブを変更しません。

制限付きWindowsサンドボックスでは、esbuildによる設定ファイルの解決時の親ディレクトリ読み取りが拒否されることがあります。その場合は許可された通常のターミナルで同じコマンドを実行してください。ゲームやビルドが他プロジェクトを書き換える処理はありません。

## 基本操作

1. 単推し／コンボ／箱推し、メンバーA〜H、初期都市を選択して開始。同じシードと同じ操作順なら同じ抽選結果になります。
2. ホームで仕事・休息・訓練・架空資産購入。全国マップでは都市を選び、直結する経路で移動します。
3. **現在の街の具体的なスポットを選択**して探索し、提示された3枚から1枚を獲得します。選択前は他の行動・週進行を保留します。
4. コレクションで所持数と保存デッキの枚数を比較。デッキ画面で減らす→追加→20枚にして保存。自動調整、初期編成に戻す、編集取消も使えます。編集途中の案は自動保存しません。
5. ホームで週を進めます。未使用APは消滅、週末収入と回復を適用。4・8・12週はライブを参加または見送りで解決する必要があります。
6. ライブでは手札の「EPで使う」で即発動。「後半へ」「次の曲へ」でCPUも行動し、フェーズが進みます。最後に必ず報酬を受け取ります。
7. 12週の公演を解決し、ホームの「12週間の旅を終える」で最終リザルト。以後は結果・カード・トロフィーを閲覧でき、リセットで再挑戦できます。

ナビ：ホーム／全国マップ／コレクション／デッキ／ライブ／トロフィー／ヘルプ。390px幅では全7項目を表示します。ライブ中はEP・スコア・コンボ数・フェーズ操作を画面上部に固定し、手札をスクロールしても確認できます。

## 実装済みルールと仮値

| 項目 | 実装 |
| --- | --- |
| 初期値 | 全都市共通：資金60,000、体力80、毎週4AP、初期24枚所持・20枚編成 |
| 仕事 | 2AP・体力12、資金+22,000 |
| 探索 | 1AP・体力8または12。スポット別資金400〜1,200＋カード三択 |
| 移動 | 接続経路ごと1〜2AP、資金1,000〜14,000、体力6×AP |
| 訓練 | 1AP・資金1,000・体力8。選んだ指標を以後の各カード使用時+2 |
| 休息 | 2AP、体力+35、上限100 |
| ファンラウンジ | 1AP・資金28,000、都市ごと1件。週末収入+1,000/件 |
| 週末 | 資金+2,000＋資産収入、体力+10（100上限）、次週AP4。最終週も収入・回復を適用 |
| 公演 | 4週東京／8週大阪／12週福岡。AP不要。現地・配信・見送り |
| 現地 | 現在地から開催都市までの最安経路費用＋4,000、体力8。基本報酬10,000 |
| 配信 | 1,500、体力0。基本報酬4,000。資金不足なら所持金全額で参加し基本報酬1,000 |
| 報酬 | 勝利なら基本報酬＋6,000とランダムSSR、敗北・引分でも基本報酬とランダムSR |

現地参加費は公演用の交通・チケット手配をまとめたゲーム内仮値です。マップの都市移動とは別処理で、滞在都市は変わりません。体力・資金・AP不足の通常行動は状態を一切変えず拒否します。体力0、資金0、AP0でも配信または見送りで公演を解決し、週を終えられます。

### カード・収集・3タイプ

- 40種類。N8 / R12 / SR12 / SSR5 / UR3。action・support・combo・finisher。すべて相違する効果定義があり、各カードにメンバー・曲属性・地域属性を持ちます。
- デッキ20枚固定、同名2枚まで、SR合計6・SSR合計2・UR合計1まで。所持数を超える編成や不明なIDは保存できません。初期はN/Rから24枚所持、最初の10種×2の適法な20枚です。
- 探索三択はスポットごとのレア度プールから抽選。同じ地域の候補を優先し、同じ三択内の重複はありません。再訪可能。編成で同名2枚を超える余剰コピーの交換機能はありません。
- 訪問したスポットの地域と一致するカードを使うたび、思い出+5。初期12種類を超える新カード1種類につき、各曲開始時の思い出+2（最大20）。収集→デッキ→ライブの反映を確認できます。
- 単推し：推しメンバーのカードに熱量+12／思い出+4。
- コンボ：条件成立したコンボカードに熱量+10／一体感+10。倍率型のコンボは参照対象の履歴が1件以上で成立します。
- 箱推し：その曲で初めて使うメンバーに一体感+10／思い出+6。
- 曲属性一致は一体感+4。地域属性は架空のゲーム分類で、メンバーの出身地等の主張ではありません。

### ライブ

- 実際の保存デッキ20枚をseeded shuffle、初期手札5枚。4曲：コール／ユニット／バラード／全体。
- 1曲4EP。前半の支出上限2EP、後半は残りEPを使えます。前半の未使用EPも後半へ持ち越し。カードを使わず進行しても詰まりません。
- 後半開始時と次曲開始時に2枚引き、手札上限7。山札が空なら捨て札をシャッフルして循環。出したカードは効果解決後に捨て札へ。手札と使用履歴は別配列です。
- 同一SRは公演全体で2回、同一SSR/URは1回。2枚編成しても使用制限は共有します。N/Rには公演回数制限なし。
- コンボは現在のカードを履歴に追加する**前**に判定。「この曲」と「公演全体」の履歴を区別。「直前」は前曲も含みます。条件未成立でも基礎効果のための使用は可能で、条件部分は不発。ログに成立・不成立を記録します。
- カードの次回強化は次の使用に一度適用。曲をまたぐ未使用の強化は消滅。手札と使用履歴は次の曲へ保持。
- CPUも20枚デッキ・同じEP・補充・効果registry・高レア制限を使用。手札の合法カードについて1手先の指標スコア増分/EPを評価する単純AI。公演によりタイプ・所持カード・訓練が変わり、固定得点ではありません。
- 各曲の目標値に対する達成率を **熱量50%・一体感30%・思い出20%** で計算。各指標の達成率上限150%。小数第1位に丸め、曲で上回った側にMVP+2点。同点ならMVPなし。4曲合計で勝敗。
- 各曲スコア、両者の総合指標、公演合計、発動ログ、コンボ履歴を表示。報酬は一度だけ受け取れます。

## ワールド・トロフィー

札幌・仙台・東京・横浜・名古屋・京都・大阪・神戸・広島・福岡・熊本・宮崎の12都市、24スポット、14本の双方向経路。地理は簡略表示です。全都市共通の初期値ですが、出発地から公演までの交通費・地域相性が違うため完全対称のバランスではありません。配信で距離による進行詰まりを避けられます。

10個の実績を自動判定：初探索／6枚獲得／3都市訪問／仕事3回／訓練3回／ライブ初参加／CPU勝利／コンボ3回／資産購入／12週終了。最終リザルトに獲得数・旅程・カード・勝利数等を反映。

五大ドーム達成は**長期モード向けのロックされた構想**です。試作版の獲得対象外。ファンラウンジは架空のゲーム資産で、実在のドームや会場の所有権を表しません。実在アイドルの写真・ロゴ、確証のない聖地や出身地主張は使っていません。

## 保存・設計

- React UIとは独立したpure TypeScriptエンジン。`act(state, action)` は入力を変更せず、新しい状態を返します。不正操作では同じstate参照を返すため、不足時にseedや資源を消費しません。
- `src/game/model.ts`：型と保存スキーマのバージョン。
- `data.ts`：40カード・都市・スポット・経路・曲・実績。カード追加はID・属性・効果配列のデータ追加で行えます。
- `deck.ts`：制限検証、自動編成。
- `live.ts`：効果処理registry、条件、手札/捨て札、フェーズ、CPU、得点。新しい効果演算はregistryへ追加します。
- `rules.ts`：行動・週・報酬・実績、移動費の最短経路計算。
- `rng.ts`：32bit LCGとFisher–Yates。`Math.random()`・時刻に依存しません。
- `save.ts`：`oshitabi.save.v1` のversion付きlocalStorage。資源・ID・デッキ・手札枚数保存則・ライブと週/未選択報酬の整合を検証。不正JSONや未知バージョンは新規設定画面に安全に戻します。
- 探索三択、途中の公演、CPU履歴、乱数seedも自動保存。リセットは確認ダイアログ後にこのゲームのキーだけを削除。ストレージが使えない場合もメモリ上で遊べ、ヘッダーに保存不可を表示します。
- 感想コピーはクリップボードのみ。権限がなければ選択可能テキストを表示。外部送信なし。感想の下書きは保存しません。

## テストと手動確認シナリオ

`npm test`：資源不足の不変条件、初期都市の公平値、収集反映、全デッキ制限、自動編成、4EP/前半2EP、seed決定性、手札上限と循環、高レア公演制限、コンボ成立/不成立、3パッシブ、40枚全カード×曲/前後半の効果解決、CPU合法行動、スコア計算、勝敗両方、報酬二重受取拒否、12週終了、全フェーズのセーブ復旧、破損・未知形式・矛盾状態の拒否。

`npm run test:smoke`：390×844のブラウザで、新規開始→具体的なスポット訪問→三択取得→横浜へ移動→自動編成/保存→仕事→週進行→3公演を手札操作で完走→報酬→12週終了。途中再読込、全体横はみ出し、感想コピー、最終セーブ再開、リセット、不正セーブからの復旧、1440pxデスクトップも検証。画面例は `test-results/mobile-live.png`、`mobile-home.png`、`mobile-finish.png`、`desktop-home.png`。

手動での確認：

1. 390px幅で初期設定から開始。ホームと全7ナビを確認。
2. 探索し三択が出た状態で再読込。候補が変わらず再開できることを確認。1枚選び、コレクションの所持差分を確認。
3. デッキを1枚減らして保存不可を確認。新カード追加で20枚に戻し保存。SR/SSR/UR制限や同名上限も確認。
4. 東京→横浜などを移動。足りないAP/資金/体力で移動ができず、資源が減らないことを確認。
5. 仕事・訓練・休息・資産購入を実行し、週末の収入と回復、体力100上限を確認。
6. 4週の公演を配信で参加。前半2EPを使い切り、後半へ。ログのコンボ成立/不成立、推し型/地域/曲の追加効果、EP・使用履歴を確認。スマホでは固定HUDから次のフェーズにも進めます。
7. 手札を使い切れない場合もフェーズ操作で4曲終了できることを確認。報酬を受け取り、8・12週の次の参加口が前回結果の下に表示されることを確認。
8. 12週を終え、最終リザルト・トロフィー・コピーを確認。再読込して結果維持、リセット取消/実行を確認。

## 既知の限界・非目標

- バランス・全価格・曲目標・CPUの強さは検証用の仮値。全シードでの勝率や各初期都市・タイプの均衡は未調整です。CPUは先読み探索や対人相当の判断をしません。
- 500カード・500スポット、オンライン対戦/同期、認証、課金、配信ストア、ランキング、長期モードは未実装。UI上で実装済みと表示しません。
- Safari/iPhone実機では未検証。実施した390pxテストはWindows Edge/Chromiumによるビューポート検証です。画面回転・ブラウザ設定の文字拡大・スクリーンリーダー全操作は網羅していません。
- セーブは端末/ブラウザ/配信元に依存。別端末同期・エクスポート・旧バージョン移行・同時タブ競合解決はありません。セーブは改ざん防止や競技向けの検証を目的にしません。
- 実績は12週内のプレイ状態に属します。リセットで消えます。獲得カードは自動編成されません。資産売却や余剰カード交換はありません。
- 外部サービス・既存サイト・認証設定・他リポジトリは触れていません。追加実装と証跡はこのプロジェクト内です。
