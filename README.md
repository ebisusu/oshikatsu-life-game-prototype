# 推し活人生ゲーム 試作版（縦断プロトタイプ）

ファンとして12週間の推し活を過ごし、第4・8・12週のライブでCPUと対決する、**ソロ＋CPU**のブラウザゲームです。
初期化 → 12週の行動 → 移動/探索/カード三択 → 20枚デッキ編集 → ライブバトル → 報酬 → 週進行 → 最終リザルト、までが最初から最後まで遊べます。

- Vite + React + TypeScript（実行時依存は react / react-dom のみ）
- ルール・データ・状態遷移は UI から独立した pure TS（`src/game/`）
- 静的ビルド（`base: './'`）なので GitHub Pages 等の任意のサブパスで動作
- 進行は `localStorage` に自動保存（バージョン付き・破損時は新規開始へフォールバック・リセットボタンあり）
- 運要素はすべてシード付き乱数（mulberry32）。同じシード＋同じ操作なら同じ展開を再現
- **オンライン／対人対戦は未実装**（今後追加予定。画面上にも明記）
- メンバーA〜H・スポット・施設・資産はすべて**架空**。実在の人物・団体・施設との関連は一切主張しません（都市名は移動拠点としての地名のみ）

## 起動・操作方法

```bash
npm ci            # または npm install
npm run dev       # 開発サーバー（スマホ実機は同一LANで --host を付ける）
npm run build     # 型チェック + dist/ に静的ビルド
npm run preview   # ビルド結果を http://127.0.0.1:4173 で確認
npm test          # 単体テスト（vitest）
npm run test:e2e  # Playwright スマホ幅390x844・PC幅1280x800で12週完走（要 npm run build 済み）
npm run balance -- 300   # ボットで300ゲーム完走させ勝率を集計
```

`npm run test:e2e` は既定でインストール済みの Microsoft Edge を使います（ブラウザのダウンロード不要）。
別ブラウザは `PW_CHANNEL=chrome npm run test:e2e`、Playwright同梱Chromiumは `PW_CHANNEL=chromium`（事前に `npx playwright install chromium`）。

### 手動プレイシナリオ（約10分）

1. 起動 → 推しタイプ（単推し/コンボ/箱推し）・都市を選び「12週間の推し活をはじめる」。チュートリアルを読む。
2. ホームで「仕事」（2AP・+¥22,000）。資金/体力/APがヘッダーに反映される。
3. マップ → 「ここを探索する」（1AP・入場費）→ 三択から1枚獲得。コレクション/デッキ画面で所持とデッキの差分（NEW・未編成）を確認。
4. デッキ画面で「−」で1枚外す（19/20 → 保存不可）→「自動調整」で20枚に戻す。新カードを＋で入れて「保存」。
5. 週を終える（週末+¥2,000・体力+10）を繰り返し、第4週へ。ホームに開催バナーが出る。
6. ライブ画面で参加方法を選ぶ（現地は会場都市へ移動・高報酬／配信／無料配信は0AP・0円）。
7. バトル：カードをタップ → 「このカードを使う」。前半は合計2EPまで、後半は残りEP。「前半を終える」→「後半を終えて次の曲へ」で4曲進行。ライブログでコンボ発動/不発の理由が分かる。
8. 結果画面で「報酬を受け取る」→ カード三択 → 次の週へ。第8・12週も同様。
9. 第12週を終えると最終リザルト（ランク・スコア・トロフィー）。「感想メモをコピー」、「もう一度」でリセット。
10. ブラウザを再読み込みしても進行が復元される。ヘルプ →「最初からやり直す」で保存削除。

## ルール（実装内容と仮の数値）

**週・資源**: 12週、毎週4AP、初期資金¥60,000、体力80（上限100）、全都市で初期値は共通。

| 行動 | AP | 資金 | 体力 | 備考 |
|---|---|---|---|---|
| 仕事 | 2 | +22,000 | -12 | |
| 休息 | 2 | 0 | +30 | |
| 探索 | 1 | -入場費 | -4〜7 | スポット1か所1回、三択カード、収集品 |
| 移動 | 1〜2 | -運賃 | -3 | 隣接都市のみ（経路は `data/world.ts`） |
| 訓練 | 1 | -800×(Lv+1) | -6 | 熱量/一体感/思い出 各Lv5まで。ライブで該当メーター+5%/Lv |
| 資産購入 | 1 | -価格 | 0 | 都市ごとの架空資産6種（週収入/ライブ補正/手札+1） |
| 週末 | — | +2,000+資産収入 | +10 | |

不足する行動は**必ず拒否**（ボタン無効＋理由表示、エンジン側でも検証）。週を終える操作はいつでも可能、無料配信は0AP・0円なので、どんな状態でも進行は詰まりません。

**カード（40種）**: N12 / R14 / SR8 / SSR4 / UR2、系統 action/support/combo/finisher。各カードに member(A–H)・songType・region・EPコスト・基本値(熱量/一体感/思い出)・効果を持ち、効果は `effects.ts` のレジストリ（34種のハンドラ）で処理。40枚すべて効果の署名・説明文が異なります（テストで検証）。

**デッキ**: 20枚固定、同名2枚まで、SR6/SSR2/UR1枚まで、所持数以内。初期コレクションは推しタイプ別に22〜27枚（合法20枚を自動構成）。

**ライブ**: 山札20枚をシャッフル→手札5→曲の切替で+2、後半開始で+1（手札上限7、山札切れは捨て札を再シャッフル）。1曲=4EP（前半は合計2EPまで、後半は残りEP）、フィニッシャーは後半専用、同名SR以上は1公演1回まで。曲タイプ（コール/ユニット/バラード/全体）にメーター補正と一致ボーナス+25%。曲スコア=熱量×50%+一体感×30%+思い出×20%、曲の勝者にMVP+2点、4曲合計の高い方が勝ち。目標スコア到達で報酬ボーナス。コンボは「この曲の使用順」「この公演の使用履歴」で判定し、手札/山札の移動とは独立。CPUは同じ規則で、手札の合法カードを効果プレビュー込みで評価して選択（前半は効率が悪いとEPを温存）。第2・4曲はCPU先攻。
参加方法: 現地（会場都市へ移動込み・獲得値×1.10・報酬×1.5・限定収集品）/ 配信（1AP・¥1,500）/ 無料配信（0AP・0円・獲得値×0.92・報酬×0.5）。体力70以上で×1.05、30未満で×0.9。

**推しタイプ**: 単推し（推しメンバーのカード×1.5＋開演時に推しカードを手札へ）/ コンボ（コンボボーナス×2.2、成功ごとに曲内+6%、各曲初回成功でドロー）/ 箱推し（使用メンバー種類×4%、一体感+10%）。

**トロフィー**: 機能16個（初ライブ/初勝利/目標達成/皆勤/全勝/5都市/全12都市/10スポット/20種カード/SSR入手/資産1・3/コンボ5回/訓練合計8/資金15万/12週完走）＋「五大ドーム制覇」は**長期モード向けのロックされた構想**（取得不可）。最終リザルトのスコア・ランクに反映。

**CPU難易度**: 公演ごとにCPUデッキ（20枚）・推しタイプ・獲得値補正（×0.97/1.14/1.10）を定義。

### 拡張方法（数百種カードへ）
`CARDS` に `c(...)` を追加し、新しい効果は `EffectParamsMap` に型を足して `EFFECTS` に `{ describe, resolve }` を1つ登録するだけです。説明文は効果定義から自動生成されるため、表示と実処理が食い違いません。

## 既知の限界・仮値

- 数値（報酬・費用・補正・CPU強度・目標スコア）はすべて仮置きで調整前。コンボ型はボットの編成では他タイプよりやや弱い（人間のシナジー構築を想定）。
- 資金は余りやすく（ボットで最終約30万円）、資産購入の優先度は低めになりがち。
- マップは地理を模した模式図（海岸線なし）。移動は隣接都市のみ（遠距離は経由）。
- スポットは都市あたり3か所・1回限り。スポットのイベント演出は未実装（収集品とカード報酬のみ）。
- ライブ中のCPUは単純な価値評価AI（先読みなし）。対人対戦・オンライン・課金・ストア配信は非目標。
- 五大ドームトロフィーと「長期モード」は構想のみ。
- 音声なし。アニメーションはCSS/SVGのみ（`prefers-reduced-motion` 対応）。
- 開発用依存（vitest/esbuild）に `npm audit` の警告があるが、配布物には含まれず本番依存の脆弱性は0件。
